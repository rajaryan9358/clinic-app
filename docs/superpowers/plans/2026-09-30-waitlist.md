# Waitlist (E3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Patients (via the portal) and staff can put a patient on the waitlist for a taken slot; when it frees up it is held for the first in line for the clinic's hold time with a WhatsApp "Book it" link, then passed on if not booked.

**Architecture:** A `WaitlistService` owns the entry lifecycle (join, offer, book, decline, remove, expire) under the same per-doctor row lock that booking uses. `AppointmentService` calls it after commit when a slot frees; portal booking checks treat another patient's active hold as taken. A scheduled command expires holds. Portal and staff get thin controllers and UI on top.

**Tech Stack:** Laravel 13, PHP 8.4, Sanctum, React 19 + Vite + Tailwind 4, PHPUnit (SQLite in-memory).

**Spec:** `docs/superpowers/specs/2026-09-30-waitlist-design.md`

## Global Constraints

- PHP `/opt/homebrew/bin/php`; tests `php artisan test`. Node `/usr/local/bin/node`; build `/usr/local/bin/node node_modules/vite/bin/vite.js build`.
- New migration file for `waitlist_entries` (`database/migrations/2026_09_30_000100_create_waitlist_entries_table.php`); **edit in place** existing migrations for `clinic_settings.waitlist_enabled` (bool default true), `clinic_settings.waitlist_hold_minutes` (unsigned int default 30), `patient_login_links.redirect_path` (string(200) null). Never migrate the MySQL dev DB except in Task 8 after a backup.
- Statuses: `waiting`, `offered`, `booked`, `declined`, `expired`, `removed`; active = `waiting|offered`. Sources: `portal`, `staff`.
- Max active entries per patient: **3**. Hold minutes validation 5–240; no settings row ⇒ enabled, 30.
- Hold expiry = min(now + hold minutes, slot start). Times in `config('app.clinic_timezone')`.
- Serialise waitlist mutations per slot with `Doctor::query()->whereKey($doctorId)->lockForUpdate()->first()` inside `DB::transaction` (same as `AppointmentService::assertSlotFree`).
- Messages (exact): 409 `Already on the waitlist for this time.` · 422 `You can be on up to 3 waitlists at a time.` · 422 `This slot is free — book it directly.` · 422 `Waitlist is not available at this clinic.` · 422 `This offer has expired.` · 409 on held slot booking `That slot was just taken. Please pick another.` · staff add for a patient already booked in that slot 422 `This patient already has this slot.`
- WhatsApp type `waitlist_slot_open`; body params `[patient full_name, clinic name, doctor full_name, date 'D, d M Y', time 'g:i A', hold minutes as string]`; URL button param = login-link token.
- Login link for an offer: account holder of the entry's patient (`managed_by_patient_id ?? patient`), `expires_at = hold_expires_at`, `redirect_path = '/waitlist/{entryId}?profile={patientId}'`.
- Staff permissions: view `appointments.view`; add/remove `appointments.create`.
- Commits: stage specific files; never stage `Clinic_Management_System_MVP_PRD.pdf`, `.playwright-mcp/`, `.superpowers/`, `public/build`. Trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Task 2: WaitlistService — join, remove, offers on freed slots, holds block others

**Files:** create `app/Services/Waitlist/WaitlistService.php`; modify `app/Services/AppointmentService.php` (after-commit `slotFreed` calls; `assertSlotFree` gains `?int $forPatientId = null`, treating an active offer for a different patient as a conflict), `app/Services/Portal/PortalBookingPolicy.php` (`freeSlots(..., ?int $forPatientId = null)` hides slots held for others; new `takenSlots`). Test `tests/Feature/Waitlist/WaitlistServiceTest.php`.

**Interfaces — Produces:**
```php
final class WaitlistService {
    public function join(Patient $patient, int $doctorId, string $date, string $start, string $source, ?int $createdByUserId = null): WaitlistEntry;
    public function remove(WaitlistEntry $entry): void;               // active → removed; if it was offered → offerNext
    public function slotFreed(int $clinicId, int $doctorId, string $date, string $start): ?WaitlistEntry; // returns the offered entry or null
    public function heldFor(int $clinicId, int $doctorId, string $date, string $start): ?WaitlistEntry;  // active offered entry, not expired
    public function isSlotOccupied(int $clinicId, int $doctorId, string $date, string $start): bool;      // any appointment not cancelled/rescheduled at that start
}
PortalBookingPolicy::takenSlots(int $clinicId, int $doctorId, string $date, int $forPatientId): array; // [{start_time,end_time}] booked or held for others, in window/notice, not already joined by the patient
```
Rules (see spec §2):
- `join`: waitlist enabled; slot on the grid (`PortalBookingPolicy::slotFor` for source portal; for staff: grid-aligned via `getDoctorAvailability` and start in the future, no window/notice); slot occupied or held for someone else, else 422 free message; patient has no appointment at that slot (portal: 409 duplicate message is for entries — for an appointment use 422 `This patient already has this slot.`); no active entry for the slot (409); active count < 3 (422). All inside the doctor lock.
- `slotFreed` (inside `DB::transaction` + doctor lock): return null if waitlist disabled, slot start ≤ now, slot occupied, or already held; pick oldest `waiting` by id; set `offered`, `offered_at`, `hold_expires_at = min(now+hold, slot start)`; issue redirect link (Global Constraints); store `login_link_id`; after commit send `waitlistOffer`.
- `AppointmentService`: `changeStatus` to CANCELLED and `reschedule` (old date/start before the move) call `notifyAfterCommit(fn () => app(WaitlistService::class)->slotFreed(...))`; wrap in try/catch + `Log::warning` like other notifications.
- [ ] **Step 1: Failing tests:** join rules (disabled, free slot, duplicate 409, limit counting staff entries, off-grid, past, patient already booked); staff join outside the portal window allowed; portal cancel frees → oldest waiting offered, second still waiting, WhatsApp row `waitlist_slot_open`, link row with redirect `/waitlist/{id}?profile={pid}`; staff cancel and reschedule-away also offer; `test_slot_freed_twice_offers_once`; `test_hold_is_capped_at_slot_start`; `test_dependent_offer_goes_to_holder_with_profile_redirect`; cancelling when nobody waits sends nothing; held slot missing from `freeSlots` for others but present for the held patient; portal booking of a held slot by another patient → 409; staff create of a held slot succeeds; `takenSlots` lists booked + held-for-others, excludes slots P already joined; remove offered → next offered.
